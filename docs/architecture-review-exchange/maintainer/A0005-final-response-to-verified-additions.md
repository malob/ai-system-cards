## New settled findings

### F33 — TOC exclusion is another correlated-authority loop

Accepted. The same `TOC_PAGES` value determines generation scope,
`EXPECTED_PAGES`, and invariant skip behavior. A shared explicit exclusion policy is
not inherently wrong; allowing it to define both omission and proof of omission
without a cross-check is wrong.

The durable fix is not three independently editable lists. It is one tracked accepted
source-page disposition inventory plus independent completeness enforcement:

- every source page is projected or carries an exact evidenced exclusion;
- a TOC exclusion records why the page is TOC and what source evidence supports it;
- P1 checks the full source-page disposition, not a range already reduced by the same
  exclusion set; and
- changing an exclusion makes coverage evidence stale rather than silently shrinking
  both generation and verification.

B did not rerun the four-page counterexample, so the exact “byte-identical flag set”
remains a static causal prediction in this record. The three confirmed call sites are
already sufficient to treat the authority loop as real.

### F34 — CI card discovery does not match site card discovery

Accepted, and I accept moving it ahead of L2. The correct repair is **not** adding a
fourth literal to the matrix. That would fix one card while preserving the defect.
CI must derive its gate set from the same repository inventory the site can publish,
or both must consume one validated registry. A discovery job feeding a dynamic matrix
or a mandatory inventory-coverage assertion is more than one YAML line, but still a
small change and the highest expected-risk reduction per unit of work.

The invariant should be explicit:

> Every card discoverable by the production site has exactly one full verifier and
> seam-gate result in the deployment dependency graph; no extra matrix entry points at
> a nonexistent card.

This also needs a test that adds a synthetic fourth card directory and proves CI
inventory coverage changes automatically. A literal-matrix snapshot test would only
move the duplication.

### F36 — Portable Markdown is a distinct, currently defective projection

Accepted. The static path confirms that `siteMarkdown()` applies the table-footnote
shim and `portableMarkdown()` does not. B reports 24 table-only footnotes whose
references remain inside raw HTML in the exports. This is not grounds for a
whole-document IR, but it is more than a hypothetical blind spot: it is evidence of a
present export-projection defect.

The repair must be verified with the actual portable output under the supported
Markdown interpretation, not by checking that the source strings still contain
`[^N]`. Required cases include one table-only footnote, multiple references to one
footnote, later prose footnotes whose numbering must remain stable, backlinks, and a
section export separated from the full-card export.

This becomes the first concrete X5 fixture. It does not meet the trigger for a
whole-document IR because the failure is localized and plausibly repairable in the
projection. If equivalent semantic patches accumulate across several export classes,
X5 can reopen that conclusion with measured evidence.
